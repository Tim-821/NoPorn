# Flight 钥匙 —— 安卓 APK 使用说明

## 这是什么

私钥长在这台手机的芯片里（Android Keystore / TEE 硬件安全区），
**连 App 自己都导不出来**。能导出的只有公钥（泄露无害）。

Mac 要装软件 → 发一个"挑战码"给这台手机 → 手机上点一下同意 →
签名发回 Mac → Mac 验证通过才会装包。

## 首次使用（装好 APK 后）

1. 打开「Flight 钥匙」App
2. 点「生成新密钥」→ 公钥自动复制到剪贴板
3. 把公钥发给 Mac 那边（微信/邮件都行，泄露无害）
4. Mac 上把这个公钥写进 `/var/db/flight/pubkey.pem`（需要管理员权限，12 月后只能由 guard 做）

## 日常使用

1. Mac 上发起安装请求，生成一条挑战码，长得像：
   `FLIGHT1|1730000000|a1b2c3d4|e3b0c44298fc1c14`
2. 挑战码发到你手机（邮件正文会带一条 `flight://sign?c=...` 链接，
   点链接自动唤起本 App 并填好）
3. 核对一下是不是自己请求的安装，点「同意并签名」
4. 响应码（96 个字符）已复制到剪贴板，同时弹出邮件草稿
   （收件人、正文都填好了），点「发送」即可
5. Mac 收到后验证签名 → 装包

## 信任模型（为什么这样做）

- 私钥：只在这台手机的芯片里，从生成起没离开过
- 挑战码：一次性，绑定时间戳 + 安装包哈希，用一次作废，30 分钟过期
- 响应码：96 字符，泄露了也没用（已消耗）
- 公钥：随便传，泄露 = 零风险
- 换密钥：点「生成新密钥」就换新的，旧公钥作废

## 注意

- 卸载本 App = 私钥永久丢失（这是特性，不是 bug）
- 换手机 = 点「生成新密钥」重新来一遍，公钥发给 Mac 换一次
- 不要 root 这台手机，root 会暴露 Keystore
